Building The People's Register

A civic publication platform engineered end to end: information architecture and design system, SEO, production deployment, then the maintenance and upgrade cadence it runs on today.

The People's Register · thepeoplesregister.co.za

ANC Nelson Mandela Region — Civic Publication

LIVE IN PRODUCTION
Discover

Product concept & content model

  • Defined the mandate: a recurring civic publication carrying editorial, field reports, and verified election information in one system.
  • Modelled the content: issues → cluster chapters → field reports, articles, metrics and community voices.
  • Designed the information architecture: journal, article, get-involved and privacy routes, sitemap before markup.
Architect

Design system & editorial architecture

  • Built the design system from zero: colour tokens, a serif-editorial / sans-UI type scale, spacing grid, component library. No framework, no template.
  • Structured the 12-page issue system (Vol. 01): editorial, six cluster chapters spanning all 60 wards, issue index and datelines.
  • Selected the stack for longevity: semantic HTML5, modern CSS, vanilla JavaScript, Python for document generation, Brevo for automation.
Build

Engineering, SEO & security

  • Engineered the interactive field journal, article pages, newsletter flows and the multilingual preference system (English / isiXhosa / Afrikaans).
  • Automated the PDF edition pipeline in Python. The same issue publishes online and as a downloadable document, revisioned on release.
  • Built the SEO architecture: unique titles and descriptions per route, canonical discipline, Open Graph cards, and JSON-LD structured data (NewsMediaOrganization · NewsArticle).
  • Hardened the platform: strict Content-Security-Policy, HSTS, a secure versioned media pipeline, and form-abuse protection.
Ship

Production deployment

  • Deployed to Vercel over HTTP/2 with cache policy, ETags and strict transport security.
  • Published robots.txt and the XML sitemap; every route indexed with preview-ready metadata.
  • Launched live with the campaign team publishing field reports through the system.
Operate & Improve

Maintenance, continuous improvement, upgrades

  • Runs the release cadence: continuous improvements, issue-based upgrades, and versioned content (PDF v2, secure asset revisions) as the platform rolls out.
  • Operates the IEC public-notice verification module, kept current against the Electoral Commission.
  • Sustains the newsletter system (double opt-in, language preferences) and the article pipeline for the next editions.

Technical writing2 samples
Shipping a trilingual civic platform on a zero-dependency stack
The platform runs on plain HTML, hand-written CSS and vanilla JavaScript. There is no build step and no dependency tree; the PDF edition is generated by a Python script. I picked this stack deliberately. Civic publishing is a long-term commitment, and long-term systems fail most often through their dependencies. A framework update breaks a build three years from now. A supply-chain issue stalls a release the week before an election. Neither can happen here, because there is nothing to update and nothing to import. The trade-off is that you write the primitives yourself. The design system, the i18n layer and the component set are yours to maintain, and that maintenance is the point. The site ships in under 500 KB, runs under a strict CSP with no exceptions, and can be audited in an afternoon. For an audience that depends on the publication, that auditability matters more than any framework feature.
Consent-first email automation: the decisions behind a double opt-in engine
The newsletter system starts from one rule: nothing is sent that was not invited. The signup form has no pre-checked boxes. A honeypot field filters bots. Subscribers receive a confirmation email through Brevo and join the list only after they click. From there the sequences run on a fixed cadence. A welcome explains what the publication is and how often it writes. Language segmentation, captured at signup in English, isiXhosa and Afrikaans, routes each subscriber to the right edition. A weekly briefing follows, then numbered alerts when each journal edition ships. Exit is one click and takes effect immediately. Deliverability is handled the boring way, with confirmed addresses only, a stable sender identity and regular list hygiene. The list grows slowly, and every message on it was asked for.
The practitioner essay1 sample
The last mile is the message
Government services are going digital, ward by ward, and the ground is not keeping up. In Nelson Mandela Bay information still moves through information tables, WhatsApp groups, community radio and doorstep conversations. A registration system only matters if a volunteer at a voting district can explain it. A publication only matters if it reads well on a phone with weak signal, in three languages. I learned this across both worlds: years in student and national politics, and now building the tools those structures publish with. The lesson is simple. Civic technology fails when it skips the last mile. So the work at Digital Origin follows three rules. Ship light enough to load anywhere. Write for the person at the table rather than the dashboard. Never assume connectivity. Institutions that build for the last mile earn trust twice: once when the message arrives, and again when people act on it.
